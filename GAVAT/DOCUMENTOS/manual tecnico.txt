6.	Configuración
En esta sección se describen las configuraciones necesarias para el correcto funcionamiento del sistema GAVAT Construcciones Arquitectónicas. Estas configuraciones permiten establecer la conexión con la base de datos, definir las variables de entorno, ejecutar el servidor backend y el frontend, y garantizar el adecuado funcionamiento de los mecanismos de autenticación y comunicación entre los diferentes componentes de la aplicación.
6.1 Configuración de las variables de entorno
El sistema utiliza archivos de configuración. env para almacenar parámetros necesarios para su funcionamiento, evitando que información sensible quede incluida directamente en el código fuente.
Entre las variables configuradas se encuentran:
Variable	Descripción
DB_HOST	Dirección del servidor donde se encuentra la base de datos.
DB_PORT	Puerto utilizado por MySQL.
DB_NAME	Nombre de la base de datos del proyecto.
DB_USER	Usuario de acceso a la base de datos.
DB_PASSWORD	Contraseña del usuario de la base de datos.
JWT_SECRET	Clave utilizada para generar y validar los tokens JWT.
REACT_APP_API_URL	Dirección de la API consumida por el frontend.

6.2 Configuración de la base de datos
El sistema utiliza MySQL como gestor de base de datos y Sequelize como ORM para administrar la comunicación entre la aplicación y la base de datos.
Antes de ejecutar el sistema se debe verificar que:
•	La base de datos exista.
•	Las credenciales configuradas en el archivo. env sean correctas.
•	El servidor MySQL se encuentre en ejecución.
•	La conexión entre la aplicación y la base de datos sea exitosa.
6.3 Configuración del servidor Backend
El backend está desarrollado con Node.js y Express.
Durante su configuración se establecen aspectos como:
•	Puerto de ejecución del servidor.
•	Configuración de CORS.
•	Procesamiento de solicitudes JSON.
•	Manejo de archivos mediante Multer.
•	Configuración de rutas de la API REST.
•	Manejo centralizado de errores.
6.4 Configuración del Frontend
El frontend desarrollado en React consume la API REST del backend mediante la dirección configurada en la variable:
REACT_APP_API_URL
Esta configuración permite establecer la comunicación entre la interfaz de usuario y los servicios del servidor.
6.5 Configuración de autenticación
El sistema implementa autenticación mediante JSON Web Token (JWT).
Después de iniciar sesión correctamente, el servidor genera un token que identifica al usuario autenticado. Este token es enviado en cada solicitud protegida y es validado por los middlewares de autenticación antes de permitir el acceso a los recursos del sistema.
6.6 Comandos utilizados
Durante el desarrollo y la ejecución del sistema se utilizan los siguientes comandos:
Comando	Descripción	Cuándo utilizarlo
npm install	Instala todas las dependencias del proyecto.	La primera vez que se descarga el proyecto o cuando se agregan nuevas dependencias.
npm start	Ejecuta la aplicación en modo de desarrollo.	Para iniciar el backend o el frontend según la carpeta donde se ejecute.
npm test	Ejecuta las pruebas configuradas en el proyecto.	Durante la verificación del funcionamiento del sistema, si existen pruebas implementadas.

6.7 Recomendaciones de configuración
Para garantizar el correcto funcionamiento del sistema se recomienda:
•	Verificar que Node.js y MySQL se encuentren correctamente instalados.
•	Configurar adecuadamente las variables de entorno antes de iniciar la aplicación.
•	Mantener actualizadas las dependencias del proyecto.
•	Verificar que el backend y el frontend utilicen la misma dirección de la API.

•	No compartir información sensible contenida en los archivos. env.


7.	Diseño de la Arquitectura Física.
7.1 Descripción de la arquitectura física
El sistema GAVAT Construcciones Arquitectónicas está basado en una arquitectura cliente-servidor de tres capas, compuesta por un frontend desarrollado en React, un backend implementado con Node.js y Express, y una base de datos MySQL administrada mediante Sequelize ORM.
Durante el desarrollo, todos los componentes se ejecutan en un entorno local, comunicándose mediante el protocolo HTTP a través de los puertos configurados para cada servicio. El frontend consume los servicios REST del backend, mientras que este interactúa con la base de datos para realizar las operaciones de almacenamiento y consulta de la información.
7.2 Nombre de los equipos
Equipo	Descripción
Equipo Cliente	Computador desde el cual el usuario accede a la aplicación mediante un navegador web.
Servidor Frontend	Aplicación desarrollada en React encargada de la interfaz gráfica del sistema.
Servidor Backend	Aplicación desarrollada con Node.js y Express que procesa la lógica de negocio y expone la API REST.
Servidor de Base de Datos	Motor MySQL encargado del almacenamiento de la información del sistema.
7.3 Ubicación física

Elemento	Ubicación
Frontend	Equipo del desarrollador (entorno local).
Backend	Equipo del desarrollador (entorno local).
Base de datos	Equipo del desarrollador (MySQL local).

Nota: Durante el desarrollo del proyecto no se implementó un ambiente de producción; todos los componentes funcionan en un entorno local.

7.7 Interrelación de conexión entre los equipos
El flujo de comunicación del sistema es el siguiente:
1.	El usuario accede a la aplicación desde un navegador web. 
2.	El navegador carga el frontend desarrollado en React. 
3.	El frontend envía solicitudes HTTP mediante Axios al backend. 
4.	El backend procesa la solicitud utilizando Express y las reglas de negocio. 
5.	Sequelize se comunica con MySQL para consultar o modificar la información. 
6.	La base de datos devuelve los resultados al backend. 
7.	El backend responde al frontend en formato JSON. 
8.	El frontend presenta la información al usuario.

Acceso a datos	Sequelize ORM.
Persistencia	Base de datos MySQL.

9.	Contingencias y soluciones.
La tabla siguiente resume las principales contingencias que pueden presentarse durante la instalación, configuración y operación del sistema GAVAT Construcciones Arquitectónicas, así como sus posibles causas, consecuencias y soluciones recomendadas. La información se encuentra basada en la implementación actual del backend, frontend y base de datos del proyecto.

Contingencia o problema	Posible causa	Consecuencia en el sistema	Solución recomendada
No es posible instalar dependencias del backend o del frontend	Node.js o npm no están instalados correctamente, o las dependencias del proyecto no han sido descargadas.	Los comandos npm install o los scripts de arranque fallan y el proyecto no puede ejecutarse.	Instalar Node.js LTS compatible con el proyecto, verificar npm --version y ejecutar npm install en el backend y en el frontend.
El backend no inicia por variables de entorno incompletas	El archivo. env del backend no existe o carece de variables como PORT, DB_HOST, DB_NAME, DB_USER, DB_PASSWORD, JWT_SECRET o JWT_EXPIRES_IN.	El servidor puede arrancar con valores no esperados o fallar al intentar conectar a la base de datos o generar tokens.	Crear o corregir el archivo. env del backend con las variables requeridas y reiniciar el servicio.
No se puede conectar con MySQL	MySQL no está en ejecución, el puerto 3306 está ocupado o las credenciales del archivo. env son incorrectas.	El backend no puede sincronizar los modelos ni iniciar correctamente y las operaciones de negocio quedan bloqueadas.	Verificar que MySQL/XAMPP esté activo, confirmar el puerto y las credenciales en. env y revisar los mensajes de conexión del servidor.
El backend no arranca porque el puerto 5000 está ocupado	Otra aplicación o una instancia previa del backend ya está utilizando el puerto configurado.	El servidor no queda disponible en http://localhost:5000 y el frontend no podrá consumir la API.	Cerrar la instancia anterior, cambiar el puerto en .env o liberar el puerto ocupado antes de reiniciar.
El frontend no se comunica con el backend	La variable REACT_APP_API_URL apunta a una URL incorrecta o el backend no está en ejecución.	Las pantallas muestran errores de red o fallos al cargar productos, usuarios y pedidos.	Ajustar REACT_APP_API_URL en el archivo. env del frontend a la URL real del backend y reiniciar el frontend.
El frontend no inicia porque el puerto 3000 está ocupado	Otro proceso ya está utilizando el puerto por defecto de React.	La aplicación no queda accesible en http://localhost:3000.	Cerrar el proceso que ocupa el puerto o cambiar el puerto de ejecución del frontend.
Fallan las peticiones protegidas por JWT	El token no se envía en el encabezado Authorization, ha expirado o la clave secreta JWT_SECRET no coincide con la configuración esperada.	El sistema responde con errores 401 Unauthorized y el usuario no puede ingresar ni consultar datos protegidos.	Iniciar sesión nuevamente para obtener un token válido, verificar que el encabezado sea Bearer <token> y revisar la configuración de JWT_SECRET y JWT_EXPIRES_IN.
No se pueden subir imágenes de productos	El archivo no tiene un tipo MIME permitido, supera el límite de tamaño configurado o no llega correctamente al middleware Multer.	La creación o edición de productos con imagen falla y el usuario recibe un error de validación.	Usar únicamente archivos de imagen con tipos jpg, jpeg, png o gif, mantener el tamaño dentro del límite configurado y enviar el archivo en el campo esperado por el formulario.
No se generan facturas PDF	La librería pdfkit no está disponible, el directorio facturas/ no puede escribirse o el proceso no tiene permisos de escritura.	La factura puede crearse en la base de datos, pero el PDF no queda disponible para descarga.	Verificar que las dependencias del backend estén instaladas, revisar que exista el directorio facturas/ y que el proceso de Node tenga permisos para escribir en él.
No se guardan imágenes ni PDFs por problemas de permisos de carpeta	El usuario que ejecuta Node.js no tiene permisos de escritura sobre las carpetas uploads/ o facturas/, o dichas carpetas no existen en el sistema.	Las subidas de imágenes y la generación de PDFs fallan o quedan incompletas.	Crear las carpetas necesarias y asignar permisos de escritura al usuario que ejecuta la aplicación. (Nota: Esta contingencia depende del sistema operativo y del entorno de ejecución).
Los cambios en variables de entorno no se reflejan inmediatamente	React y el backend cargan las variables al iniciar el proceso, por lo que los cambios no se aplican hasta reiniciar.	El sistema continúa utilizando la configuración anterior y pueden aparecer errores de conexión o rutas incorrectas.	Reiniciar el proceso del backend y del frontend después de modificar los archivos. env.
